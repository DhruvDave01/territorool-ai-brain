## F01 — Login and session
- **Platform:** both
- **Entry:** mobile cold start without JWT → `Login`; web `/login`
- **Steps:** enter email + password → submit → token/session created → role-based landing
- **Success:** mobile → `Dashboard` (or `SubscriptionGate` if the trial is inactive). Web → Admin `/hq/dashboard`, Business Agent `/manager/dashboard`, others `/dashboard`
- **Failure cases:** invalid credentials; inactive account; Business Sales Agent whose manager is inactive or has no subscription (web); Business Agent on mobile ("not authorized"); session expiry (mobile 401/403 → Session Expired modal; web redirect to login; manager portal 419)
- **Criticality:** **BLOCKER**
- **Screens:** mobile `Login`, Session Expired modal (`App/App.js:401-429`); web `resources/views/auth/*`
- **Endpoints:** API `login`, `logout`, `recovery`, `reset`, `renewtoken`; web `Auth\LoginController`

## F02 — Registration and post-signup onboarding
- **Platform:** both
- **Entry:** mobile Login → "Register Here"; web `/register`, `/trial`, `/b2b`
- **Steps:** name/email/phone/password/country → account created → onboarding preferences → paywall/plan
- **Success:** user created with a package and credits → Dashboard
- **Failure cases:** duplicate email; invalid phone/email; reCAPTCHA (web); store purchase cancelled
- **Criticality:** **BLOCKER** (raised from HIGH by owner 2026-09-15)
- **Screens:** mobile `Register` (`register/index_register_split.js`), `PostSignupPaywallFlow` (visual capture deferred); web `Auth\RegisterController`, `Auth\B2bSignupController`, `Auth\PostRegistrationOnboardingController`
- **Endpoints:** API `mobileregistration`, `leads_user`, `updateUserPreferences`, `validate-phone`; web `register`, `onboarding/preferences`, `b2b`

## F03 — Subscription, paywall, upgrade, cancel, buy extra credits
- **Platform:** both (different billing rails)
- **Entry:** mobile `SubscriptionGate` / `SubscriptionScreen` / Settings buttons; web `/subscription/*`
- **Steps:** choose plan → pay (mobile: App Store/Play via RevenueCat; web: Stripe/PayPal) → backend sync → entitlements/credits updated
- **Success:** active subscription, credits allocated
- **Failure cases:** payment failed/cancelled; backend sync failure after a successful charge (July audit H16); cancel only records feedback (July audit H12–H14)
- **Criticality:** **BLOCKER**
- **Screens:** mobile `SubscriptionScreen`, `SubscriptionGate`, `SettingsPlanPaywall`, `CancelAccountConfirmModal` (visual capture deferred); web `SubscriptionController` views, `/special`
- **Endpoints:** API `revenuecate-success`, `revenue-subscription-update` (webhook), `cancelSubscription`, `request-package-upgrade`; web `subscription/subscribe`, `subscription/payment`, `subscription/upgrade`, `subscription/credits-addon`, `subscription/paypalTrnComplete`
