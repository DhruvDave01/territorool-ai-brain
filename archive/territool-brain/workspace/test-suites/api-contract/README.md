# API contract suite (layer L3)

Asserts the V2 API envelope and the fields the **mobile app** and the **MCP modules** depend on, so a web-side change cannot silently break either consumer. This is what `qa-gate.md` **QG-8** requires.

```bash
# from territool-brain/
node workspace/test-suites/api-contract/run.js --list                 # cases, no network
node workspace/test-suites/api-contract/run.js --env staging          # run everything
node workspace/test-suites/api-contract/run.js --env staging --only F01
node workspace/test-suites/api-contract/run.js --env staging --role "Sales Agent"
node workspace/test-suites/api-contract/run.js --env staging --json workspace/test-suites/api-contract/last-run.json
```

Exit 0 when every case passed or was a recorded known gap; 1 on any FAIL. **BLOCKED never counts as a pass.**

## Rules this suite obeys

- **Staging only.** `lib/env.js` hard-wires the base URL, throws on any other host, and `call()` refuses any URL outside that base. `--env staging` is mandatory.
- **Credentials** are read from `.local/test-accounts.md` at run time and never printed: `redact()` scrubs credentials, JWTs and emails from every message and from the JSON report.
- **No paid or destructive calls.** Only endpoints a case names are ever requested. Anything that spends credits, purchases, syncs a CRM, or deletes is out of scope until the owner sets up test payments (05-testing.md §7.4).
- **Data it does create** is tagged `QA-AUTO-…` and disclosed in the case file.

## Adding a flow

One file per flow in `cases/`, exporting `{ flow, title, priority, cases[] }`. Each case declares `id`, `title`, `type`, `role`, `refs`, optional `knownGap`, and `async run(t, { account })`. Use `t.is / t.eq / t.ok` for assertions and `t.blocked(reason)` when the environment cannot support the case — never fake a pass. Mirror every case as a `TC-<flow>-nnn` row in `workspace/test-cases/<flow>-<slug>.md` (format: `brain/audits/05-testing.md` §6).
