**Content:** four principles — Think Before Coding, Simplicity First, Surgical Changes, Goal-Driven
Execution. Read in full. No prompt injection, no instructions to run commands, exfiltrate, or fetch
anything. The advice is sound and well written.

### Why it was NOT installed as a skill

1. **Redundant with stronger, enforceable rules already here.** Each principle already exists in a
   Territool-specific form that names files, roles and commands, where the source is generic:

   | Principle | Already covered by |
   |---|---|
   | Think Before Coding | `S0.5` never invent facts; `territool-loop` §1.3 + the VERIFIED/VISUAL/DOCUMENTED/INFERRED/UNKNOWN ladder; router's one-question rule |
   | Simplicity First | `CG-A7` "Searched before creating"; `territool-code` §1 with the actual grep commands |
   | Surgical Changes | `S0.2` **New code only**; `CLAUDE.md` rule 2; `territool-loop` §1.4 "no drive-by refactors" |
   | Goal-Driven Execution | router "Acceptance criteria (numbered, testable)"; bug route writes the failing reproduction first; `QG-6` |

2. **Skill-routing cost.** Its `description` claims "writing, reviewing, or refactoring code" — a third
   skill competing with `territool-router` and `territool-loop`, which already conflict (open item).
3. **Licence is ambiguous.** No LICENSE file, so by default all rights are reserved, while the skill
   frontmatter claims MIT. Vendoring the file verbatim on that basis is not clean. Adopting *ideas*,
   rephrased in our own words with attribution, is unaffected by that ambiguity.
4. Installing a redundant "Simplicity First" skill would break its own principle 2.

### What WAS adopted — two genuine gaps it exposed

Both were confirmed absent by search before being added:

| New rule | Why it earns its place |
|---|---|
| **`S5.7` Clean up your own orphans, only your own** | The brain had **nothing** on orphans. It also resolves a real ambiguity in `S0.2`: "new code only" could be read as "never delete anything", which would leave a change with broken, unused leftovers. The boundary is now explicit — your own orphans go, pre-existing dead code is reported. |
| **`S5.8` The change is proportionate to the problem** | The brain had **no** size or over-engineering heuristic at all. |

Enforcement added: **`CG-A11`** in `code-gate.md`. Measured here rather than assumed — `no-unused-vars`
fires on this codebase at **warn** level (probe run 2026-09-16 against `repos/mobile/.eslintrc.js`), and
`static-checks.js` only FAILs on severity 2, so the item is `REVIEW` and says so. It is not written up
as an automated gate it cannot be.

### Not verified

- The originating post (`x.com/karpathy/status/2015883857489522876`) was not fetched; the attribution is
  reported as the repo's claim, not as established fact.
- The star count is extraordinary for a 28-commit, 20 KB repository. It comes from the GitHub API and is
  recorded as-is; popularity was not treated as evidence of quality either way.
