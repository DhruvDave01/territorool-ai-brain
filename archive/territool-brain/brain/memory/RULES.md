# Knowledge memory — the laws

Part I of the owner's "Knowledge Vault — Install / Audit Prompt (V2)", verbatim (adopted 2026-09-17). In this brain
the vault is called **memory** (`brain/memory/`) because "vault" already means the Obsidian vault (owner decision Q1).
Everything else in `brain/memory/` is mechanism; these are permanent.

**LAW 1 — Append, never destroy.** Knowledge that becomes wrong is marked
`SUPERSEDED` and linked forward. Knowledge about deleted code is `STALE`, not
removed. The exception is narrow and specific: duplicate noise, corrupted generated
content, secrets, and meaningless temp data may be removed. Useful project
intelligence never may. If unsure, keep it.

**LAW 2 — Evidence or nothing.** Every claim carries a classification and a source
that resolves. `INFERRED` never becomes `VERIFIED` without new evidence. Never
fabricate a commit SHA, date, test result, QA result, screenshot, or verification.

**LAW 3 — One canonical home per fact.** A fact lives in exactly one entry.
Everything else references it by id. Views and indexes are generated, never
hand-copied. Duplicated facts drift, and drifted facts are worse than absent ones.

**LAW 4 — Idempotent.** Running sync twice with no project change must produce zero
new entries. Search → compare → dedupe → classify → only then write.

**LAW 5 — Growth must not degrade the brain.** The vault may reach thousands of
entries. A task must still load only what it needs. If loading knowledge gets slower
as the vault grows, the retrieval layer is broken and takes priority over adding
more knowledge.

**LAW 6 — Never overwrite human work.** Uncommitted changes in the working tree are
someone's in-progress thinking. Never revert, never overwrite, never assume
obsolete. Surface the conflict instead.

**LAW 7 — No false completion.** `NOT RUN`, `UNKNOWN`, `PARTIAL`, `CONFLICTED`,
`NEEDS-VERIFICATION` are correct answers. A truthful incomplete vault is more useful
than a falsely complete one. Never edit knowledge so indicators appear green.

## How each law is enforced here

| Law | Enforcement | Where |
|---|---|---|
| 1 | `supersede` keeps the old entry with `status: SUPERSEDED` + `superseded_by`; lint fails a SUPERSEDED entry with no successor and any broken chain; the brain is under git from baseline `5d7214e` | `tools/memory.js` (supersede, lint), `_generated/SUPERSESSION-MAP.md` |
| 2 | lint: every entry has `evidence` + `source`; a `VERIFIED` entry must cite something checkable, and cited paths and evidence artefacts must exist | `tools/memory.js lint` |
| 3 | register tables are **rendered** from entries (`render --check` fails on drift); `_generated/` is rebuilt, never edited; versions have one home (`stack.md` §0, `version-drift` lint) | `tools/memory.js render`, `reindex` |
| 4 | ids are content hashes (`<date>-<hash6>`) of a stable key; migrate, seed-git and sync are re-run in the self-test and must add 0 | `tools/memory.js --self-test` |
| 5 | tasks load `HOT.md` + `context <query>` (capped at 25, commit history ranked last); nothing loads `INDEX.md` whole | `_generated/HOT.md`, `context` |
| 6 | sync lists uncommitted work as NEEDS-VERIFICATION and never ingests or edits it; migration refuses a dirty register unless every change is logged | `tools/memory.js sync`, `migrate` |
| 7 | QA reports are PARTIAL unless coverage is complete; `NEEDS-VERIFICATION` / `UNKNOWN` are first-class statuses; `status` prints counts only | `tools/qa-report.js`, `tools/memory.js status` |
