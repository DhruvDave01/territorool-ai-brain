# qa-report.js criticality regex had a stray Arabic character and a pattern-order bug

## What

The criticality pattern contained `\س` (U+0633) instead of `\s`, so it never matched; after fixing the character the name-only pattern still matched first and kept criticality blank. All 18 generated QA reports showed "Criticality: —". Fixed both (criticality pattern first).

## Why it matters

BLOCKER and HIGH features were not flagged in any QA report, so the regression tiering that depends on criticality was blind.

## Evidence

tools/qa-report.js (flows.md parser) · workspace/qa-reports/2026-09-17-knowledge-memory-audit.md finding 2

## Implication for future work

Scan generated tooling for non-ASCII inside regexes and string literals, and prove a scanner works by running it on the character it targets. When fixing a regex, check that an earlier alternative cannot shadow the fixed one.
