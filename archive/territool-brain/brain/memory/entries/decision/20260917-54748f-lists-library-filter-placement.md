# Placement: a filter on the Lists library (mobile `LS-20`)

## What

**Routing:** **PLACE** on mobile, because a filter narrows the same collection the screen already searches.
**No new UI on web:** `/lists` already has a grid filter row.

**Added:** a filter at the trailing end of the mobile search row, as a sliders button with the applied dot. It
opens the existing "Filter By" modal pattern (`LS-41/42`).
- Fields: exactly web's — name, company count, date range.
- Filtering runs on the device over the loaded `lists[]`.

**Candidates:**

| Candidate | Result | Reason |
|---|---|---|
| Trailing button | **won** | Address Book pattern; nothing moves vertically |
| Leading button | rejected | List details convention, which is now a defect (UI-UX-06) |
| Chip row | rejected | pushes every card down; only right for 2–3 fixed sorts |
| Header icon | rejected | competes with the primary action (+) |
| Per-list "…" menu | rejected | wrong scope: it acts on one list |
| Bottom sheet | rejected | would be a second panel pattern |

**Interactive groups: 7 → 8.**
- Before: back · create · search+clear · open list · per-list menu · scroll hint · tab bar.
- Added: filter.
- The owner ruled that the filter is its own group, because it serves a different intent.

**Per platform:**
- Web: inline filter row (existing).
- Mobile: modal.
- The difference is intentional (screen width) and recorded in `parity-map.md` F11.

## Why it matters

- **This closes a parity gap; it isn't a feature.** Web has filtered lists by name, size and date all along, while
  mobile only searches names.
- Matching web exactly closes the divergence without opening a new one.

## Implication for future work

- **The Lists screen is at the complexity gate.** The **next** addition goes to **EXTEND or a restructure proposal,
  not PLACE**, even if it is small. Hold this line when a "one more small thing" request arrives.
- New criteria ("shared with me", "unread", "assigned by manager") land on **both platforms together** (UI-UX-07).
  They never go to mobile alone.
- The filter button is built on tokens. Address Book's hard-coded copy stays until the shared component lands
  (UI-DX-02), so **two implementations exist on purpose** for now.
- **Implementation is held** until incident `VAULT-20260917-ef8968` (production config) is closed.
