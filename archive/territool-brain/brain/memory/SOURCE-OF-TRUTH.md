# Source of truth — which source wins, per question

There is no single hierarchy. The right authority depends on the question (V2 Part III; owner evidence priority of
2026-09-16 in `brain/context/contradiction-register.md`).

| Question | Authority | Not the authority |
|---|---|---|
| What does the code do now? | The code in `repos/mobile`, `repos/web` (current checkout) | docs, memory |
| What should it do? | Approved requirement / owner decision (`decision` and `question` entries with `origin: user-statement`, `brain/context/conventions-shared.md` S3) | the code |
| What should it look like? | Approved design / owner screenshots (`brain/context/design-system.md`, `mobile-screenshot-index.md`) | the current render |
| What does the running app do? | Runtime observation on staging (`qa` entries, `workspace/qa-evidence/`) > current screenshots/video > design docs | old notes |
| What does the API promise? | The contract suite (`workspace/test-suites/api-contract/`), then the implementation. **A difference is a `conflict` entry.** | old docs |
| What data exists? | Schema + migrations (`brain/context/data-model.md`, generated from the repo) | assumptions |
| Why is it like this? | `decision` entries, then git history (`change` / `fix` entries) | guesses |
| Which version is installed? | `brain/context/stack.md` §0, checked against `package.json` / `composer.lock` by `wiki-lint` | any copy |
| What was tested, and did it pass? | `last-run.json` + `tools/qa-report.js` reports (coverage-based) | a passing-looking summary |

## Rules

- **A bug report means current behaviour is not intended behaviour.** Never resolve a code-vs-requirement conflict
  by deferring to the code.
- **When reliable sources disagree**, write a `conflict` entry with:
  - both sources and both claims;
  - the observed behaviour and the impact;
  - whether a human decision is needed;
  - any temporary working assumption, clearly marked.

  Never pick silently. A resolved conflict becomes `RESOLVED`, and its history stays.
- **Dated records** (audits, evidence rows, QA reports, `log.md`, commit entries) keep what was true when they were
  written. The living notes in `brain/context/` are corrected instead, with a `correction` entry holding both claims.
