# Knowledge memory — start here

The permanent, append-only memory of the Territool project: decisions, bugs, fixes, conflicts, questions, evidence,
incidents and the commit history, each as one typed entry.
- `brain/context/` is the **distilled current truth** a task loads by default.
- `brain/memory/` is the **full record and evidence** behind it.

Owner decisions of 2026-09-17 (Q1–Q7, F8) are in `workspace/qa-reports/2026-09-17-knowledge-memory-audit.md`.

## What is here

| Path | What | Written by |
|---|---|---|
| `RULES.md` | the seven laws, and how each is enforced | owner (verbatim) |
| `SCHEMA.md` | entry format, ids, evidence mapping, write-time guards | hand, enforced by lint |
| `SOURCE-OF-TRUTH.md` | which source wins, per question | hand |

| `entries/<type>/` | the knowledge, one fact per file | `memory.js` + Claude (never Codex) |
| `_templates/` | prose of the six migrated registers, with `<!-- memory-row: ID -->` placeholders | `memory.js migrate` |
| `_generated/` | INDEX · HOT · BY-FEATURE · BY-FLOW · BY-PLATFORM · KNOWLEDGE-GRAPH · COVERAGE · FRESHNESS · CONFLICTS · GAPS · ORPHANS · SUPERSESSION-MAP · CHANGES | `memory.js reindex` / `sync` |

**The six registers are rendered from entries.** Their tables in `brain/context/` keep their paths and IDs, so every
existing citation still resolves:
- `open-questions.md`
- `UNKNOWN_REGISTER.md`
- `UPCOMING_IMPROVEMENTS.md`
- `known-fragile.md` §5
- `contradiction-register.md`
- `evidence-ledger.md`

To change a row, edit the entry's `ROW:` line (or supersede the entry), then run `render`. To change prose, edit the
template.

## How a task uses memory (wired into `brain/skills/territool-router/LOOP.md`)

```bash
node tools/memory.js sync                 # INTAKE: new commits, uncommitted work, env pointers, freshness
cat brain/memory/_generated/HOT.md        # GROUND: always
node tools/memory.js context F11          # GROUND: the task's features / files / words (max 25)
node tools/memory.js impact repos/mobile/App/components/list/index.js   # IMPACT + PLAN risks
node tools/memory.js history F11          # when the "why" matters
node tools/memory.js new --type decision --title "…" --source "USER SAID 2026-09-17" \
  --what "…" --why "…" --implication "…" --features F11 --origin user-statement --approver owner   # POST-SYNC
node tools/memory.js supersede <old-id> <new-id>   # the only way to change what an entry means
node tools/memory.js reindex && node tools/memory.js lint --strict
```

Slash commands wrap these. ## Capture paths

| Source of knowledge | Path into memory |
|---|---|
| A loop task (any terminal state, including BLOCKED and FAILED) | POST-SYNC → `memory.js new` (decision / fix / failed-approach / regression-link / correction) |
| A commit by anyone | `memory.js sync` (pull-based; no git hooks, owner decision Q5) → `change` / `fix` / `failed-approach` |
| Uncommitted human work | listed in `_generated/CHANGES.md` as NEEDS-VERIFICATION, **never ingested** (Law 6) |
| Codex | Codex writes only `workspace/handoff/<date>-<slug>/result.md`; Claude reads it and captures the outcome (owner decision, Codex boundary) |
| A PR / code review (Bitbucket web, GitHub mobile) | read-only; decisions made in review → `decision` entries with the PR link as source |
| Owner statements | `origin: user-statement`, `approver: owner` |
| Environment pointers (mobile API base, MCP configs) | `sync` records them; a production value becomes a NEEDS-VERIFICATION `environment` entry |

## Honest limits

- Memory is reconciled only when `sync` runs (loop INTAKE, `/memory-sync`, the brain-sync Stop hook). Nothing watches
  the repos in between.
- Commit entries carry the commit message and file list only (DOCUMENTED). They say *that* something changed, not
  whether it works.
- Migrated rows keep an upper-bound date (`≤2026-09-17`), because the brain had no git history before baseline `5d7214e`.
