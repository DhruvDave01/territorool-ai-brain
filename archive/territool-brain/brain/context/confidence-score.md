# Confidence score: how ready the brain is for a task

**Owner decision 2026-09-16 (USER SAID "approved").** The owner asked for a score for "how confident
you are when I give you any task". This is that score. It measures what the brain **holds** for each
product feature, not how capable the agent is.

```bash
node tools/brain-score.js                  # overall + every feature
node tools/brain-score.js --feature F08    # a task's features, and what would raise each
node tools/brain-score.js --self-test      # proves the formula below
```

`brain-start.js` prints the one-line version at the end of every start.

## Formula

Every feature F01–F32 (`brain/context/flows.md`) scores 0–100 across five parts, 20 points each.

| Part | 20 | 10 | 0 |
|---|---|---|---|
| **Code** | code files linked to the feature | only app screens linked | nothing |
| **Behaviour** | screenshots or screen recordings | only app journeys or screens | nothing |
| **Parity** | settled: owner-confirmed, identical, single-platform or n/a | known to differ ("accidentally different") | UNVERIFIED or *proposed* |
| **Tests** | test cases (10) + a suite file (10) | one of the two | neither |
| **QA** | a QA report with verdict PASS or PASS-WITH-NOTES | — | none |

**Overall** = the average weighted by criticality: BLOCKER ×4, HIGH ×3, MEDIUM ×2, LOW ×1. A task that
touches several features scores their weighted average.

## How evidence is found

- Code, behaviour and parity come from the brain index (`brain/audits/data/brain-index.json`), so
  **run `node tools/brain-sync.js` first** after changing notes.
- Tests and QA count by file name. They must start with, or contain, the feature ID:
  - `workspace/test-cases/F08-*`
  - `workspace/test-suites/**/F08-*`
  - `workspace/qa-reports/<date>-f08-*.md`

  A QA report only counts when its `Verdict:` line says PASS or PASS-WITH-NOTES.

## Limits (accepted with the formula)

- **It checks only that something is there.** F08 has 17 known problems linked and still scores 50.
  The tool shows the problem count next to each score so it is not missed.
- **It leaves out machine setup** (`tools/doctor.js`) and the open owner items. Both appear separately
  in `brain-start`.
- **It is not a quality verdict.** The definition of done is still a `territool-qa` PASS.
