Result per item: PASS / FAIL / N/A with evidence. **The gate passes only if no item is FAIL.**

| ID | Check | Pass criterion |
|---|---|---|
| TG-1 | Test cases written in the approved format: `workspace/test-cases/<Fxx>-<slug>.md` **and** `.csv` with all columns | both files exist; header matches §6 exactly |
| TG-2 | Scope stated: **full flow** or **impacted-only**; impacted flows derived from `known-fragile.md` §1–§4 (tiers + graphs) | scope line + list of flows with the tier that triggered each |
| TG-3 | Priority inherited from flow criticality (BLOCKER P0, HIGH P1, MEDIUM P2, LOW P3) | every row's priority matches `flows.md` |
| TG-4 | Coverage per changed behaviour: **happy**, **validation** (every required field + format, per platform), **permission per role** (Sales Agent, Business Sales Agent, Business Agent, Admin where relevant), **negative**, **offline/network failure**, **edge data** (empty, long, special chars, limits e.g. 400 stops), **parity** (mobile/web/API same rule), **visual** (design gate refs), **provider failure** for every external call touched (timeout, 401/403 bad or missing key, 429, 5xx, malformed JSON), **credit side effects** (applies once; repeat event doesn't apply again; missing balance row) | each type present or N/A with a reason (provider failure + credit side effects added Phase 7) |
| TG-5 | Known gaps referenced in the `Known gap` column (KG-*/BT-n) instead of being silently expected to pass | all related gaps listed |
| TG-6 | Every automatable P0/P1 case has automation in `workspace/test-suites/{api-contract,web,mobile}` and the `Automation` column points to it | none missing; manual only for camera/push/store purchase/device-only |
| TG-7 | **Exact commands** to run each suite are listed (runnable by Claude Code or Codex), including device/UDID or base URL | commands present and copy-pasteable |
| TG-8 | Target is **staging** only; runners abort on non-staging hosts | guard present in each runner |
| TG-9 | Data policy: read-only by default; created data prefixed `QA-AUTO-YYYYMMDD-` with teardown; `@spends-credits` tag on any credit/payment/sync/send test (not run without the test-payment setup); registration tests tagged on-demand | tags and teardown present |
| TG-10 | No secrets in test cases, suites or output (credentials read from `.local/test-accounts.md` at runtime) | grep for key/password patterns = 0 |
| TG-11 | V2 changes include API contract cases for **mobile and MCP consumers** (fields, types, `status` semantics) | contract cases present |
| TG-12 | Mobile selectors use semantic testIDs (no order-based `…Dup7` IDs) for new automation | none |
| TG-13 | Suites were executed at least once and results recorded in the `Status` / `Last run` columns | statuses filled (Pass / Fail / Blocked / Known gap) |
