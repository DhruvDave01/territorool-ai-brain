# Design Gate

Run by `territool-design` (proposals/specs) and `territool-qa` (implemented UI). Reference: `brain/context/design-system.md`.

Result per item: PASS / FAIL / N/A with evidence (spec section, screenshot path, file:line). **The gate passes only if no item is FAIL.**

## A. Spec completeness (proposals in `workspace/design-proposals/`)

| ID | Check | Pass criterion |
|---|---|---|
| DG-A1 | Current state audited first: existing screens of the flow listed with screenshot paths | ≥ 1 screenshot per existing screen (mobile `IMG_*` / capture, web `shoebox/03-web/screenshots/**` or fresh capture) |
| DG-A2 | Every element specified with **token names** (colour, type, spacing, radius, elevation), no raw values | spec has no hex/px/pt literals outside the token table references |
| DG-A3 | All states enumerated per screen: default, loading, refreshing (mobile lists), empty, error, disabled, validation errors, long content, offline (where data loads) | each state has a row |
| DG-A4 | Mobile **and** web variants defined for shared flows (or marked intentionally different with the parity-map reason) | both variants or a parity-map citation |
| DG-A5 | Interactions and transitions described (tap targets, navigation, confirmations, toasts) | present |
| DG-A6 | Copy uses glossary terms; dates in D-DS7 formats; enums humanised; required fields marked | reviewer checklist |
| DG-A7 | Accessibility: text/background pairs meet contrast rules (≥ 4.5:1; ≥ 3:1 only for ≥ 17 pt/px bold); hit targets ≥ `size.touch-min` | contrast listed for every coloured text pair |
| DG-A8 | Implementable without further questions: components mapped to existing reusable components or new ones named with file paths | no open "TBD" |
| DG-A9 | **Project assets only:** every font, icon, logo, image and colour in the spec or mockup comes from `brain/assets/` (tokens, fonts, icon-fonts, icons, brand, images). No external font or icon CDN, stock or placeholder images, or invented colours | grep the proposal for `fonts.googleapis`, `http(s)://` asset URLs and hex values not in `tokens/` → 0 (added 2026-09-15, USER SAID) |

## B. Implemented UI (QA)

| ID | Check | How | Pass criterion |
|---|---|---|---|
| DG-B1 | No hardcoded colours / font sizes in changed code | `static-checks.js` `M8-*` / review CSS diff | 0 findings |
| DG-B2 | Only approved tokens used (`tokens.js` / `--tt-*`) | review diff | token names match `design-system.md` |
| DG-B3 | Font is DIN (mobile `fonts.dinCondensed*`; web `DIN 2014`) | review diff; web: Playwright computed `font-family` | no system/Inter/Lato/DM Sans/Space Grotesk in new UI |
| DG-B4 | Buttons: only the 5 variants; disabled = 40% opacity | screenshot + code | — |
| DG-B5 | Segmented controls / chips follow rules 2–3 | screenshot | — |
| DG-B6 | Screen shell rules (mobile header + sheet; portal nav < 768 px) | screenshots mobile 390 pt; web 1440/768/390 + `tools/probe-styles.js` layout signals | at 390: a visible menu control reaches every nav item (off-canvas items with `inViewport: false` don't count); **no fixed banner/overlay covers content or controls**; no horizontal overflow |
| DG-B7 | Every specified state reachable and matches the spec | screenshots per state | — |
| DG-B8 | Contrast of new text pairs | compute from tokens; web: `probe-styles.js` `contrast`; text on gradients/images measured at the **lightest stop** | meets DG-A7 for every pair, including avatar initials and pills |
| DG-B9 | Visual regression on untouched screens in the change's risk tier | screenshot comparison vs baseline | no unintended differences |
| DG-B10 | Copy/glossary/date formats in the running UI | screenshots | — |
| DG-B11 | **Colour meaning:** success colours only for success; errors use `color.danger-text` (+ `danger-subtle`); `color.brand.primary` only for actions, links and selected state (not plain data values); teal only as fill/icon | code + screenshot | no success-green error messages, no link-blue non-links (added Phase 7) |
| DG-B12 | **Touch/click targets:** interactive elements ≥ `size.touch-min` (mobile 44, web 40) in height, or padded hit area | `probe-styles.js` element `height` | all row actions, pagination and chips meet it (added Phase 7) |
| DG-B13 | **No new external design dependencies** in changed code: no new `fonts.googleapis`/font CDN links, no new icon library, no remote images; icons come from the surface's existing set (mobile react-native-vector-icons sets, portal lucide-react, Blade FontAwesome 4.4 / Ionicons 2.0.1) | diff review + grep | 0 findings (added 2026-09-15) |
