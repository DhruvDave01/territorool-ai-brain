## Verdict rules

| Verdict | When |
|---|---|
| **PASS** | All applicable items pass, **including QG-13 and QG-14**; no failures other than unchanged known gaps |
| **PASS-WITH-NOTES** | All BLOCKER and HIGH checks pass. Only MEDIUM/LOW findings, unchanged known gaps, or MEDIUM/LOW checks blocked by environment remain, each listed as a note with an owner or follow-up |
| **FAIL** | Any code/design/test gate FAIL; any new or worsened defect; any BLOCKER or HIGH check failing **or unverified** (blocked BLOCKER/HIGH verification counts as FAIL unless the owner waives it in writing); production touched; secrets exposed |

**Standing owner waivers (USER SAID 2026-09-15; they count as waived, not as unverified):**
- **Payment / credit-spend confirm steps:** no staging test-payment setup. Flows are verified up to the step before paying.
- **Admin role checks:** no Admin account for now.
- **Staging PHP version:** target is 7.4.33.

Each waived check is listed in the report's Notes as `Waived (owner)`.

**Report each state separately. They never imply each other:**
`IMPLEMENTED` ≠ `TESTED` ≠ `QA VERIFIED` ≠ `VISUALLY VERIFIED` ≠ `RUNTIME VERIFIED` ≠ `KNOWLEDGE SYNCED`.
- Code that looks right is not tested.
- Passing tests are not QA.
- A successful compile is not runtime behaviour.

**Future-session test (QG-13):** could a new session, starting tomorrow without this conversation, understand from the
repo plus `brain/memory/` alone what changed, why, and what to watch? If not, the knowledge is still stuck in the
conversation: capture it before the verdict.

A FAIL returns to `territool-router` with a defect list (see `brain/skills/territool-router/LOOP.md`).
