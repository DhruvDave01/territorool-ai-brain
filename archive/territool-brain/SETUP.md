# Set up the Territool brain

For a new team member, on a new machine. **One command does everything.**

```bash
node tools/brain-start.js
```

It asks which tools you use, checks they are actually installed, reports exactly what is missing and
how to fix it, notices anything new dropped into the inbox, rebuilds the brain, and tells you what is
open. It never installs anything for you and it never guesses.

---

## 1. Prerequisites

Only two things are truly required: **Node 18+** and **git**. Everything else depends on what you
intend to do, and `brain-start` tells you which of those you're missing.

## 2. Get the brain

The sharing mechanism is not decided yet — the owner will pick one of: git with media in LFS, git with
media shared separately, or a plain copy. Whichever it is, you end up with a `territool-brain/` folder.

## 3. Point it at your own checkouts

`repos/mobile` and `repos/web` are **symlinks to the owner's machine** and will not resolve on yours.
`brain-start` detects this and tells you. Fix it with your own paths:

```bash
rm -f repos/mobile repos/web
ln -s /your/path/to/TerriTool_Mobile repos/mobile
ln -s /your/path/to/webterritool     repos/web
```

Nothing else in the brain hard-codes a machine path.

## 4. Credentials

`.local/` is never shared — not in git, not in a zip. Ask the owner for `test-accounts.md` and put it at
`.local/test-accounts.md`, then `chmod 600 .local/test-accounts.md`. Staging only. Never copy a
credential into a note, a report, a commit or a chat.

## 5. Tell the brain which tools you use

```bash
node tools/brain-start.js --tools cursor,codex --jobs api-contract,web-unit
```

Supported tools: `claude` · `codex` · `cursor` · `copilot`.
Jobs: `mobile-static` · `mobile-unit` · `web-unit` · `api-contract` · `web-e2e` · `mobile-e2e`.

Stored in `.local/profile.json` — personal to you, never committed, asked only once.

## 6. Open it in your tool

| Tool | What it reads | Notes |
|---|---|---|
| Claude Code | `CLAUDE.md` + `brain/skills/` | `cd territool-brain && claude` |
| Codex | `AGENTS.md` | **Do not open Codex with `repos/web` as its working directory** — it can reach production (details: `brain/context/tooling.md` §3) |
| Cursor | `.cursor/rules/territool-brain.mdc` | applies automatically |
| Copilot | `.github/copilot-instructions.md` | |

Those three files are **generated** from `brain/context/agent-brief.md`. Never edit them by hand — edit
the brief and run `node tools/sync-agent-files.js`.

---

## Adding things to the brain

Drop anything — docs, screenshots, recordings, exports, notes — into **`shoebox/00-INBOX/`**.
`brain-start` reports what's new and suggests where it belongs. Nothing is filed automatically.

## Keeping it current

```bash
git pull                      # if the brain is in git
node tools/brain-start.js     # re-checks your setup and rebuilds
```

The brain rebuilds itself after every Claude Code turn via a `Stop` hook, so it is normally already
current. `node tools/brain-parity.js` proves the Obsidian vault and the shared graph still agree.

## The rules you are agreeing to

Never touch production · new code only · repos read-only outside an explicit task · never commit or push
unless asked · credentials stay in `.local/` · stop before any pay step · never weaken a check to make
it pass · never invent a fact.

Full text: `brain/context/conventions-shared.md` §S0. Short version for any tool: `AGENTS.md`.
